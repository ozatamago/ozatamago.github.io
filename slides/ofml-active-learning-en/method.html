Object-Flow Machine Learning

Protocol-Structure-Preserving Surrogate Modeling

In the Problem setting, we defined the true execution process by protocol-dependent unknown maps \(\{F_{j,p}^\dagger\}\) and defined the OFML hypothesis class (shared modules \(g_{\theta_j}\); composed predictor \(\Eval(p;\theta;x)\); parameter uncertainty \(\Pi_n^\theta\) and its pushforward to the terminal function \(\Pi_n^{G}\)) in §3.3. This section presents in boxes the concrete composed architecture, learning, and closed-loop selection (formal definitions in §3.3; consistency in the Theory).

Surrogate model with protocol structure

Composed execution rule (architecture)

The shared modules \(g_{\theta_j}:\Zcal_j\to\Scal_j\) and observer read-out heads \(h_q\) from the Problem setting §3.3 (\(\theta\in\Theta\) bundles all learnable components of the operation modules and observer heads) are composed in the topological order of the same DAG as the true execution:

\[ z_v^{\theta}(x) = \iota_{p,v}\!\left((s_u^{\theta}(x))_{u\in\Pa_p(v)},\, x\right),\qquad s_v^{\theta}(x) = g_{\tau_p(v)}\!\left(z_v^{\theta}(x)\right). \]

The observation prediction collects the read-outs of the observer nodes: \(\Eval(p;\theta;x)=\left(h_q(s_{v(q)}^{\theta}(x))\right)_{q\in\Obs(p)}\in \Ycal_p^{\mathrm{obs}}\). Replacing the true execution \(F_{\tau_p(v),p}^\dagger\) with the learnable components \(g_{\tau_p(v)}\) yields the OFML surrogate model, which concretizes the execution rule of the hypothesis class of §3.3. In the main setting the terminal read-out \(h_{q^{\mathrm{term}}}\) is a terminal scalar measurement, and the intermediate observer heads in 1-C are learnable.

The core of OFML: parameter sharing per operation type = the mechanism of transfer

Even when the same module type \(M_j\) appears in different protocols, at different positions, and with different numbers of occurrences, the same prediction component \(g_{\theta_j}\) is used. This parameter sharing is the sole mechanism of knowledge transfer across protocols. A black-box surrogate model that treats an entire protocol as a single categorical feature or a flat feature vector does not make this operation-level sharing structure explicit.

Learning from observational data

Terminal supervision only (no intermediate traces)

OFML assumes no supervision signal from per-operation local input-output traces or from intermediate latent states. What is given directly during training is only the observations that collect the measurement-node outputs, and all prediction components \(\{g_{\theta_j}\}\) are learned jointly from the observation prediction error across the entire protocol.

Empirical risk minimization

For the dataset \(\Dcal_n=\Dcal_{\mathrm{src}}\cup\Dcal_{\mathrm{tar},n}\),

\[ \mathcal L_n(\theta) = \sum_{i} \ell_{p_i}\!\left(y_i,\ \Eval(p_i;\theta;x_i)\right) + \lambda\,\Omega(\theta), \qquad \widehat\theta_n\in\operatorname*{arg\,min}_{\theta\in\Theta}\mathcal L_n(\theta). \]

\(\ell_{p_i}\) is a loss on the observation space \(\Ycal_{p_i}^{\mathrm{obs}}\) (MSE, negative log-likelihood, etc.), and \(\Omega\) is a regularizer. All \(g_{\theta_j}\) are learned jointly from the terminal measurement error across the entire protocol (no per-operation local supervision is used).

Identifiability is nontrivial

This objective does not directly supervise the per-operation local maps. To what extent each module component can be identified from the observation outputs alone is nontrivial, and it is treated in the Theory as local input coverage and target-relevant identifiability.

Uncertainty-aware prediction and closed-loop selection

Implementation of the parameter uncertainty \(\Pi_n^\theta\) (§3.3)

In the main implementation, the parameter uncertainty \(\Pi_n^\theta\) of §3.3 is approximated by a deep ensemble of \(M=5\) (differing seeds) (MC-dropout / HMC are alternative \(\Pi_n^\theta\); for point estimation only, \(\Pi_n^\theta=\delta_{\widehat\theta_n}\)).

Predictive distribution = pushforward to the terminal function

The predictive distribution of a candidate \((p,x)\) is the pushforward \(\Pi_n^{G}=(T_p)_{\#}\Pi_n^\theta\) of §3.3, i.e., for any measurable \(B\subseteq\Ycal_p^{\mathrm{obs}}\), \(\Pi_n^\theta(\{\theta:\Eval(p;\theta;x)\in B\})\). The predictive mean and covariance are

\[ \mu_{n,p}(x)=\E_{\theta\sim\Pi_n^\theta}\!\left[\Eval(p;\theta;x)\right],\qquad \Sigma_{n,p}(x)=\Var_{\theta\sim\Pi_n^\theta}\!\left(\Eval(p;\theta;x)\right). \]
Acquisition function and closed-loop selection

From the predictive distribution \(\Pi_n^{G}\), the acquisition function \(\alpha_n(a)=\alpha(a;\Pi_n^{G},\Pcal_\star)\) (MaxVar / IVR / SUR) is computed, and the next experiment is chosen by \(a_{n+1}\in\operatorname*{arg\,max}_{a\in\Acal_n}\alpha_n(a)\) (the action \(a=(p,x,q)\) of §3.5, unit cost). After obtaining the observation \(y_{n+1}=\Eval^\dagger(p_{n+1};x_{n+1})+\xi_{n+1}\), it is added to the data \(\Dcal_{\mathrm{tar},n+1}\) and the model is retrained sequentially.

Concretization in the experiments

In our experiments the vocabulary is \(\{A,B,C,D,M\}\) plus an embedding \(\text{embed}\) plus a terminal observer \(O\). Since the protocols are serial, execution reduces to s = embed(x); for op in steps[:-1]: s ← g_op(s); y = obs(s) (non-residual \(s_v = g_{\theta_{\tau_p(v)}}(z_v)\)). The uncertainty in the main implementation is a deep ensemble of \(M=5\); MC-dropout / HMC are alternative \(\Pi_n^\theta\). For the baseline methods and the architecture, see the Experiments setup.
